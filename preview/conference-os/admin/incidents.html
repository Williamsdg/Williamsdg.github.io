Module 08 · Operator Reference

Incidents & Crisis Command.

System of record for every incident from SEV-1 (crisis) to SEV-4 (routine). Auto-opens from NWS, Replay, Social Listening, manual entry. Every incident has a chain-of-action timeline; every action is WORM-logged.

08.1

Active Incident Board

REAL-TIME

List of all open + monitoring incidents. Each row: icon, severity, description, venue/game link, elapsed time.

Data Sources

  • incidents table — open + monitoring rows
  • Sort: severity DESC, then elapsed DESC
  • Click → open incident detail

Manual Inputs

  • + New Incident button — opens entry form
  • Auto-opens from NWS lightning · Social spike · Replay outage · etc.

Configurable Controls

  • Auto-refresh interval (default 10s)
  • Default sort
  • Collapse SEV-4 / SEV-MON by default (off)
  • Per-category color

Permissions & Audit

SAC office + Event Staff full view. Schools see incidents at their venue. Every open + ack + close + edit WORM-logged.

08.2

Incident Detail panel (chain-of-action)

REAL-TIME

Per-incident: meta (owner, escalated to, next assess), chain timeline (each step timestamped + owner), category-specific fields.

Data Sources

  • incident_events — one row per chain step
  • Playbook step list pre-populates chain on incident open
  • Status auto-advances on key acks

Manual Inputs

  • Owner marks each chain step as complete
  • Add note at any point
  • Edit ETA / next-assessment time

Configurable Controls

  • Per-playbook step list (admin-editable)
  • Auto-page rules (SEV-1 = all chain, SEV-2 = primary owner + backup)
  • Auto-create-Comms-thread on incident open

Permissions & Audit

Incident owner edits. Head of Security edits any. Schools at venue see read-only. Every step logged.

08.3

Conference Live Map

REAL-TIME

Regional map with pins colored by status (green = OK, info = WX, danger = medical, warn = security).

Data Sources

  • Venue lat/lon from venues
  • Pin color computed from active incidents at venue

Manual Inputs

None — auto-rendered from incidents.

Configurable Controls

  • Pin auto-refresh (default 30s)
  • Show inactive venues (default off)
  • Wall-mode rotation (rotates with game board)

Permissions & Audit

All SAC roles view. Schools see only own venue's pin highlighted.

08.4

Escalation Chains

EVENT

9 chains (one per category) defining who's auto-paged when incident opens. Visible on its own tab.

Data Sources

  • escalation_chains table — chain_id + ordered_steps
  • Each step: role + named owner + ack-required flag

Manual Inputs

Head of Security defines chains; updated when org changes.

Configurable Controls

  • Chain editor with drag-reorder
  • Step skip-on-ack rules
  • Cross-chain triggers (SEV-1 fires all chains)

Permissions & Audit

Head of Security edits. Auto-page actions WORM-logged.

08.5

Playbook Library (26)

EVENT

Pre-baked runnable playbooks per common situation (lightning hold, mass casualty, field rush, etc.). One-click "Run".

Data Sources

  • playbooks + playbook_steps tables
  • Run = creates incident with pre-populated chain steps

Manual Inputs

  • Playbook author drafts new playbooks
  • Run button opens incident with step pre-fill

Configurable Controls

  • Playbook editor (admin)
  • Per-playbook default severity
  • Per-playbook required-role list

Permissions & Audit

Head of Security edits. Any SAC ops role can run. Each run = audit row.

08.6

After-Action Reports (AARs)

EVENT

Auto-drafted within 24h of incident close. Owner finalizes. Lessons captured to playbooks.

Data Sources

  • Auto-draft pulled from incident_events timeline
  • Comms Hub thread excerpts joined
  • Owner adds narrative

Manual Inputs

  • Owner finalizes within 24h
  • Lessons-learned bullets added
  • Playbook updates suggested

Configurable Controls

  • Auto-draft template per category
  • SLA window (default 24h)
  • Auto-escalation if AAR overdue

Permissions & Audit

Owner finalizes. Head of Security can edit anytime. AARs WORM 7yr.
