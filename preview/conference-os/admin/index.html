How each module page is organized

Section by section. Same structure every page.

For each visible UI section (a panel, a card, a table, a widget) on each module, you get four blocks side by side:

Data Sources

Every system, feed, or table that flows into this section. Includes refresh cadence (real-time / event / daily / manual), source of truth, and notes about latency or fallback.

Manual Inputs

What a human has to type in, upload, or click for this section to work. Includes who types it in (role + named owner) and when (game-day, weekly, on event).

Configurable Controls

What an admin can change about how this section behaves. Threshold values, refresh intervals, role gates, default views, color-coding rules.

Permissions & Audit

Which of the seven role types can view, edit, and configure. What every action writes to the audit trail. Whether the section is school-scoped, sport-scoped, or conference-wide.

Foundational concepts

Things that are true everywhere.

00.1

Identity & role gates

SYSTEM

Every screen, dataset, and action is gated by role. Schools see only their schools. Officials see only their crews. The SAC office sees everything.

Seven Roles

  • SAC Executive — full read/write
  • Sport Administrator — sport-scoped
  • School — own-school-scoped
  • Official — own-crew-scoped
  • Replay Center — replay system access
  • Media Partner — broadcast + assets
  • Event Staff — event-scoped

Configurable Per-Role

  • Module access (which of the 12 visible)
  • Read vs. Edit per section
  • Sport filter defaults
  • School scope (if school role)
  • Notification preferences
  • Wall-display permission
00.2

Refresh cadence taxonomy

REAL-TIME

Every data source in the platform has one of four refresh patterns. Knowing which one applies tells you how fresh the data on screen is, and whether a change you make will be visible immediately.

Real-time (WebSocket push)

Game scores, replay rulings, weather advisories, incident events, chat messages, social mention spikes. UI latency under 2s. Used where action depends on instant awareness.

Event (push on change)

Crew assignments, credential issues, policy distributions, school submissions. Updates pushed when the underlying record changes. Latency under 10s.

Periodic (15-min / hourly / daily)

Attendance, broadcast ratings, NCAA submission status, hotel pickup rates. Polled or batched on a schedule. Trade freshness for cost.

Manual (user input)

Memo drafts, ruling text, AAR narratives, sponsor deliverable status. Entered by a human; persisted on save.

00.3

Audit-by-default

SYSTEM

Every consequential action — credential issued, memo distributed, violation logged, access grant, score posted, replay ruled — writes to a tamper-evident audit log retained 7 years per NCAA Bylaw 32.7. Every module writes; the Compliance module surfaces.

What's logged

  • Actor (user + role + IP)
  • Action (verb + target)
  • Before/after values (if applicable)
  • Timestamp + module
  • Tied to incident/case/submission ID

What's not logged

  • Reads (too noisy)
  • UI navigation
  • Search queries
  • Heartbeat pings
