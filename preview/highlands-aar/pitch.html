The Problem

The Knowledge Exists. It Just Doesn't Go Anywhere.

This isn't a problem of effort — campus teams debrief constantly. It's a problem of format. When 26 campuses each record a weekend differently, none of it aggregates, and the lessons live in individual memory until that person changes roles.

How a weekend gets recorded today

  • Notes in a text thread, a doc, or nowhere
  • Every campus uses a different format
  • Central Ops chases 26 people for status
  • Wins and misses are told, not logged
  • Layouts get rebuilt from memory each year
  • Action items die in a group chat
  • When a staff member leaves, so does the history

How it works with Highlands Ops

  • One structured report, every campus, every event
  • Identical fields, so 26 campuses actually compare
  • Reporting status visible at a glance — no chasing
  • Notes roll up into one searchable network feed
  • Layouts are saved, versioned, and compared year over year
  • Action items carry an owner, a due date, and a status
  • The institution keeps the knowledge, not the individual
The Model

Borrowed From Places Where the Debrief Is Non-Negotiable

The military and large hospital systems run After Action Reports for a simple reason: at scale, verbal debriefs don't survive contact with the next event. The same structure fits a 26-campus church remarkably well — high repetition, high volunteer turnover, and a hard deadline every single Sunday.

📋 Capture

The same structured report after every event — attendance, setup, production, facilities, weather, guest experience, wins and misses.

🔭 Compare

Shared fields mean Central Ops sees the whole network in one view instead of reading 26 different documents on Monday.

↻ Carry Forward

Layouts, playbooks and open items persist, so next Christmas begins from last Christmas rather than from a blank page.

Why It Matters

What Changes on a Monday Morning

⏱ The chase disappears

Reporting status is visible on the dashboard. Nobody spends Monday texting 26 campuses asking whether they've written anything down.

🔁 Problems stop repeating

When the same issue is logged at four campuses in the same format, it stops being four separate conversations and becomes one fix.

🎄 Big events get easier every year

Christmas, Easter and conferences are the highest-stakes, lowest-frequency events. Saved layouts and playbooks are worth the most exactly there.

🏆 Volunteers get seen

Recognition captured in the moment reaches leadership instead of being forgotten by Tuesday. Retention follows being noticed.

🧭 New campuses launch faster

Campus 27 opens with 26 campuses' worth of documented process instead of one person's best recollection.

🛡 Turnover stops costing history

The knowledge lives in the system. When a role changes hands, the operating history stays with the church.

Biggest Impact

Full Event Operations Platform

Run every event type — Sundays, Motion Nights, conferences, Christmas — on one system with the layouts and playbooks that make next year easier.
Phase One + Two
  • Everything in the Reporting Pilot
  • Visual Operations with saved, versioned layouts
  • Playbooks per department and event type
  • Campus Blueprints — permanent facility profiles
  • Recognition wall across all campuses
  • Photo galleries and document library

Connected Ministry Intelligence

Make the platform answer questions on its own and talk to the tools your teams already run every weekend.
Phase Three
  • Everything in the full platform
  • Planning Center integration
  • ProPresenter and production tooling
  • Live weather tied to each report
  • AI report summaries and year-over-year comparison

On investment: a build at this scope typically lands in the range of a mid-five-figure platform engagement, with ongoing hosting and support handled separately — the spread depends almost entirely on integration depth and how many event types launch in year one. Before we talk numbers, the more useful conversation is which of these would create the biggest operational difference for Central Ops in the next twelve months.
Straight Answer

What's Real in the Demo, and What Isn't

Worth stating plainly so nothing is oversold.

✅ Genuinely built

Every screen, tab, form, filter and navigation path works and is clickable. The 26 campuses are Highlands' actual locations. The interface is fully responsive on mobile.

⚠️ Simulated for the demo

All data is realistic but invented. Planning Center, ProPresenter, live weather and the AI features are mocked to demonstrate the interaction — a production build connects them to real services.

A production build means: the same interface on a modern application framework with a secure database, real integrations, genuine AI summarization, role-based permissions per campus, single sign-on for staff, and a proper rollout plan across all 26 locations.
