HOW TO READ THESE DOCS

Each module page is structured the same way.

Once you've read one, the rest go fast.

  1. What this module does — the operating problem it solves, in two paragraphs.
  2. Who uses it — the SEC office team that owns it + the constituents (schools, officials, broadcast partners) who interact with it.
  3. Data sources — every system, feed, or input that flows into the module, with refresh cadence and source-of-truth notes.
  4. How to monitor it — the day-to-day rhythm of who watches what, when, and what they're looking for.
  5. KPIs leadership should hold this to — measurable outcomes the platform should improve, with current baseline + target.
  6. How it connects to other modules — the dependency map, so a change in one module is visible everywhere it touches.
i

The structure is intentional.

Leadership shouldn't have to ask "what does the system do?", "where does this data come from?", and "is it working?" in three separate meetings. Every module page answers all three.

FOUNDATIONAL CONCEPTS

The five things that are true everywhere in the platform.

Each module is built on the same data and identity foundation. These five concepts apply across every page in the docs.

1. One identity layer · seven role types.

Every user is one of: SEC Executive, Sport Administrator, School, Official, Replay Center, Media Partner, or Event Staff. Every screen, dataset, and action is gated by role. Schools only see their schools. Officials only see their crews. The SEC office sees everything.

2. Sport-aware everywhere.

The platform was built knowing the SEC runs 21 sports, not just football. Every module exposes a "Sport" selector to filter the view down to just the sport in question. This matters when, say, the same dashboard needs to surface Iron Bowl ops in November and the SEC Softball Tournament prep in May.

3. Real-time where it matters, batch where it doesn't.

Game-day events (scores, replays, incidents) update in real time over WebSockets. Operational data (rosters, hotel blocks, NCAA submissions) updates on event triggers. Analytical data (ratings, attendance trends) refreshes nightly. The platform doesn't pretend everything is real time — that would be wasteful and brittle.

4. Auto-routing between modules.

The Social Listening module catches a sentiment spike on a crew? It auto-creates an Incident. A school files a film complaint? It auto-routes to the Coordinator of Officiating and starts a 72-hour SLA timer. The platform is wired so the right team sees the right thing without an email forward.

5. Audit-by-default.

Every action — a credential issued, a memo distributed, a violation logged, an access grant — is written to a tamper-evident audit log retained for seven years per NCAA Bylaw 32.7. The Compliance & Governance module surfaces the log; every other module writes to it.
